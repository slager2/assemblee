# Оценка: набор задач и метрики

Зачем: сравнивать режимы обвязки (сейчас `strict`, дальше «богатый» словарь `--vocab rich`, режим с подкачкой картинок)
**числами**, а не на глаз. Как в Timeline-Bench ([research.md §1.4](research.md)): самооценке агента верить нельзя,
поэтому все метрики считаются программно из папки прогона (EDL, события, mp4), без LLM.

## Как запускать

```sh
python3 scripts/eval.py --list                                   # задачи
python3 scripts/eval.py --dry -n 2                               # все задачи с поддельной LLM (без GPU)
python3 scripts/eval.py --tasks pitch3 fast30 -n 3               # настоящая модель, режим strict
python3 scripts/eval.py --tasks pitch3 fast30 -n 3 --label rich -- --vocab rich   # всё после -- уходит в `assemblee run`
python3 scripts/eval_report.py evals/results/<stamp>.jsonl [ещё.jsonl ...]          # таблица по группам (label)
python3 scripts/eval_report.py --runs runs --match сделай --group-by run           # любые старые прогоны
```

- `eval.py` без `--dry` отказывается работать, если сервер модели не отвечает (`/health`).
- `--dry` запускает настоящий `Agent` (настоящие движки, рендер, события) с `evals/fake_llm.py` через
  `evals/dry_agent.py` — так же, как `scripts/dry_run.py`, без правок кода агента. Кэш каталогов для сухих
  прогонов отдельный (`evals/.cache-dry`, копия настоящего каталога), чтобы «описания» поддельной модели не
  попали в настоящий `.cache/catalogs`. Аргументы после `--` превращаются в именованные аргументы `Agent`
  (`--review-rounds 1` → `review_rounds=1`); неизвестные (пока `--vocab`) записываются в `eval.json` как `ignored_args`.
- Каждый прогон получает `runs/<id>/eval.json` (`task_id`, `label`, `repeat`, `dry`, аргументы); строки результатов —
  в `evals/results/<stamp>.jsonl`, лог — рядом `.log`, CSV по прогонам — рядом `.csv`.
- Группировка: `--group-by label` (по умолчанию: режимы), `task`, `label+task`, `run`. Ячейка — среднее ± std по прогонам.
- Старые прогоны без `eval.json` сопоставляются с задачей по тексту `task.json`; группа — `task.json.vocab`/`mode`,
  если есть, иначе `strict` (`dry_run.py` для поддельной модели).

## Задачи (`evals/tasks/*.json`)

Поля: `id`, `task` (по-русски), `assets_dir`, `briefs[]`, `seconds`, `must_mention[]`, `sections_hint`, `notes`,
необязательно `fetch`. Элемент `must_mention` — строка или список синонимов (`["Server Beast", "Чудище сервера"]`):
засчитывается, если на экране есть любой из вариантов.

| id | материал | с | что проверяет |
|---|---|---|---|
| `pitch3` | `refs` + 3 GDD | 60 | та же задача, что у четырёх реальных прогонов «сделай-…»; три игры, решение в финале |
| `teaser-last-online` | `refs/last-online` + GDD | 45 | медленный хоррор; всего 8 картинок → повторы |
| `teaser-server-beast` | `refs/server-beast` + GDD | 45 | яркий быстрый кооп |
| `teaser-spider` | `refs/spider` + GDD | 45 | окна «Системы», тёмные looks |
| `fast30` | `refs` + 3 GDD | 30 | темп: короткие кадры против времени на чтение |
| `slides-mouthwashing` | 10 PNG-слайдов, без брифа | 45 | «покажи слайды прикольно»: текст внутри картинок, порядок, длина кадра |
| `family-fetch` | `evals/fetched/семья` (`"fetch": "семья"`) | 30 | заглушка под онлайн-подкачку; пока папки нет — `skipped: needs-fetch` |

## Метрики

Всё считается в `scripts/eval_report.py` из `summary.json` (итоговый EDL), `events.jsonl`, `task.json` и `output/*.mp4`.
Стрелка в таблице: ↑ — больше лучше, ↓ — меньше лучше, без стрелки — описательная.

| метрика | как считается | зачем |
|---|---|---|
| `score` | среднее (×100) определённых для прогона компонент 0..1: exported; `max(0, 1 − duration_err/0.5)`; reading_ok; readable_last; must_mention; unique_assets; variety; audio_ok; `1 − black_share`; tool_ok | одна цифра для быстрого сравнения; разбирать всё равно по строкам |
| `exported` | `summary.ok` и mp4 существует | успех прогона |
| duration error | `abs(длительность mp4 − seconds) / seconds` (если mp4 нет — длина EDL) | попадание в хронометраж |
| shots, cards | число кадров в итоговом EDL, из них карточек | масштаб монтажа |
| avg / min shot | средняя и минимальная длина кадра, с | темп (Timeline-Bench: агенты держат планы слишком долго) |
| reading-time violations | кадров, где `символов текста / 14 > секунд кадра` (подпись; у карточки — заголовок + подзаголовок) | текст успевают прочитать |
| repeated assets | картинок-кадров минус уникальных картинок | повторы без причины |
| variety: motion / look / transition / effect / caption style | `число разных значений / min(число использований, размер словаря)`; переходы — только не-`cut` | разнообразие; знаменатель не наказывает короткие ролики и не даёт больше 1 |
| shots with text | доля кадров с подписью или карточкой | насколько ролик «текстовый» |
| must_mention coverage | доля ключевых фраз задачи, найденных на экране: `text_match(текст кадра, фраза) ≥ 0.6` (та же нечёткая функция, что в агенте) хотя бы для одного кадра | выполнены явные пункты брифа |
| vision readable, 1st / last round | доля кадров с вердиктом `text_readable` в первом и последнем раунде review (раунд из имени `shotNN-rK.png`) | читаемость по мнению модели-зрения; рост 1st→last = review чинит |
| schema/validation warnings | поправки обвязки при сборке секций (`build_section.warnings`) + `warnings` в ответах инструментов | сколько раз модель промахнулась мимо словаря/диапазонов |
| tool errors | `tool_result.ok = false` у действий модели (шаги обвязки `h*` не считаются); делятся на **invalid** (нарушен контракт инструмента: лишние/нет полей, неизвестная секция, нет кадра) и **policy refusals** (корректный вызов, отклонённый правилом: «уже 8 звуков», «glitch уже дважды») | в `score` идёт только `1 − invalid/calls`: отказ по правилу — не ошибка модели |
| LLM retries/warnings | события `warning` (повторы после невалидного JSON и т.п.) | надёжность ответов |
| LLM requests, tokens, wall time | `summary.llm` (запросы считают и вызовы зрения), `summary.wall_seconds` | цена режима |
| audio present | у mp4 есть аудиодорожка и `volumedetect` mean > −40 dB | музыка/звуки не потерялись |
| black frames share | `blackdetect=d=0.3:pix_th=0.10`, сумма чёрных отрезков / длина | чёрные дыры в монтаже (короткие `dip_to_black` < 0.3 с не считаются) |

Ограничения: `must_mention` ищется в подписях и карточках, а не в тексте внутри картинок (для слайдов это
ожидаемо низко); readability — мнение 4B-модели зрения; variety ничего не говорит о том, уместен ли выбор.
Метрики «вкуса» (сюжет, выбор планов) программно не меряются — для них нужен человек или сильная модель-судья.
