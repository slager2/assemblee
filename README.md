# assemblee

Локальный ИИ-монтажёр: маленькая модель (Qwen3.5-4B со зрением, llama.cpp) монтирует вертикальные ролики
из картинок и брифов через настоящие open-source движки **FilmCraft** (NLE) и **EffectCraft** (моушн-графика),
а веб-монитор показывает в реальном времени, что агент сейчас делает.

## Как это устроено

Модель принимает только решения, всё ремесло и арифметику делает обвязка:

| Фаза | Кто | Что |
|---|---|---|
| explore | обвязка | читает брифы, строит каталог картинок (описания делает модель-зрение, кэш по mtime) |
| plan | модель | раскадровка: 3–8 секций, цель, длительность, музыка, стиль (JSON-схема) |
| build | модель ×N слотов | кадры каждой секции параллельно; id картинок — enum в схеме, выдумать нельзя |
| — | обвязка | минимальное время на чтение подписи, подгонка секций под длительность, нормализация значений |
| polish | модель | список правок (JSON-действия): эффекты, звуки, порядок, музыка |
| director | зрение (`--director`) | контактный лист всего монтажа + раскадровка → критика и правки, до 2 раундов |
| review | обвязка + зрение | сборка, рендер каждого кадра с текстом, модель-зрение судит «читается/нет», модель чинит |
| export | обвязка | компиляция EDL → FilmCraft → H.264 |

Монтаж хранится как **EDL** (данные), а таймлайн FilmCraft каждый раз собирается из него заново
(`assemblee/compiler.py`). Поэтому модель может переставлять и удалять кадры, а не только дописывать в конец.

Подробности и источники: [docs/research.md](docs/research.md), протокол событий: [docs/events.md](docs/events.md),
настройка сервера модели: [docs/llm-tuning.md](docs/llm-tuning.md).

## Запуск

```sh
scripts/make_audio.sh                 # один раз: синтезировать музыку и звуки (.cache/audio)
scripts/serve_llm.sh start agent      # 4B + зрение на :8011
python3 web/server.py --runs runs --port 8765 &   # монитор: http://127.0.0.1:8765
python3 -m assemblee run --assets ~/Рабочий\ стол/refs \
    --brief ~/Рабочий\ стол/"Last Online — GDD.md" \
    --task "Сделай необычный вертикальный питч трёх наших игр" --seconds 60
scripts/serve_llm.sh stop
```

### Режим «на максимум»: меньше обвязки, больше решений модели

| Флаг | Что делает |
|---|---|
| `--guardrails full` (по умолчанию) | как раньше: обвязка сама подгоняет секции под длительность, вставляет карточку с главной мыслью, режет переходы до 2 на секцию, берёт картинки только из `asset_group`, поднимает время кадра до времени чтения |
| `--guardrails light` | остаётся только валидация (enum в грамматике, клампы, нечёткие исправления, жёсткий минимум 0.8 с для кадра с текстом). Всё остальное — **замечания** в промпте полировки («главная мысль не в кадре», «секция 14 с при цели 8 с», «текст читается ~2.4 с, на экране 1.2 с», «картинка стоит дважды»), модель решает сама. `asset_group` — подсказка, схема разрешает все картинки |
| `--guardrails off` | как light, но без замечаний о времени чтения и без удаления повторов |
| `--think [--think-budget 1024]` | раскадровка и сборка секций с размышлением Qwen3.5 (бюджет токенов на запрос); мысли идут в монитор как `[мысли] …`, JSON-грамматика действует на ответ после мыслей |
| `--planner 9b` | план, сборка и полировка на Qwen3.5-9B, зрение (каталог, режиссёр, проверка) на 4B; свап llama-server через `scripts/serve_llm.sh` только на границах фаз: 4B → 9B → 4B |
| `--director` | после полировки: контактный лист всего монтажа (кадр на план, номера), зрение смотрит его вместе с раскадровкой, пишет критику и правки (те же JSON-действия), до 2 раундов. По умолчанию включён при light/off |
| `--max` | `--vocab rich --guardrails light --think --planner 9b --director --music web` |
| `--surprise` | модель **сама** придумывает концепцию (тему, крючок, почему удивит), группы картинок с поисковыми запросами и настроения музыки; обвязка их только скачивает (`--task` можно оставить открытым: «Удиви меня») |
| `--music web` | настоящая музыка с открытой лицензией (Openverse/Jamendo, ccMixter), темп и «дроп» без модели, склейки подгоняются под бит |
| `--ideas / --no-ideas` | 36 рецептов приёмов и 14 формул крючка из `assemblee/ideas.py` как необязательное вдохновение (по умолчанию в rich) |

Полный «минимум влияния обвязки»:
```sh
python3 -m assemblee run --max --surprise --seconds 40 --task "Удиви меня."
```

Бюджет мыслей по фазам (замерено: каждый запрос съедает весь бюджет): концепция — полный, раскадровка 5/8,
сборка секции 1/4, действия режиссёра — без мыслей. Раскадровка задаёт крючок первых 2 секунд, финал (пик/обрыв/петля),
число кадров и стиль подписей каждой секции. Тяжёлые эффекты (`glint`, лучи, свечение) — не больше 3 кадров на ролик:
это бюджет рендера, а не вкуса. Перерендер любого прогона без модели: `scripts/reexport.py runs/<id>`.

Живые замеры (RTX 3050 6 GB, тизер 20 с, refs + один GDD, `--think-budget 1024`):

| Прогон | Всего | план | сборка | полировка | режиссёр | проверка | экспорт | свапы | токены мыслей |
|---|---|---|---|---|---|---|---|---|---|
| `--max` (Server Beast) | 701 s | 84 s | 246 s | 36 s | 99 s | 84 s | 143 s | 5.2 + 4.6 s | 6186 |
| `--max` (Spider Ascension) | 823 s | 84 s | 261 s | 207 s | 97 s | 30 s | 135 s | 4.3 + 4.1 s | 6186 |
| `--guardrails off --think --director`, только 4B | 418 s | 65 s | 167 s | 42 s | 26 s | 80 s | 38 s | — | 6186 |

Мысли почти всегда занимают весь бюджет: на 9B это ~60 s на запрос раскадровки/секции, на 4B ~25 s.
Сборка на 9B — две секции параллельно (профиль `planner` с двумя слотами).

Проверки без модели: `scripts/smoke_compile.py` (движки), `scripts/dry_run.py` (весь агент с поддельной LLM),
`scripts/fake_run.py` (демо-поток событий для UI).

## Картинки из интернета (`assemblee/fetch.py`)

Если своих картинок нет, обвязка находит их сама: `gather(task, llm, dest)` просит модель разбить задачу на
2–5 смысловых групп и 3–8 поисковых запросов **на английском**, ищет в **Openverse** (CC/PD, по умолчанию
только лицензии, разрешающие коммерческое использование и изменение) и **Wikimedia Commons**, скачивает
(≤ 15 МБ, короткая сторона ≥ 600 px, JPEG/PNG/WebP, проверка Pillow, отсев почти-дубликатов по dHash),
затем модель-зрение проверяет каждую картинку на соответствие сцене и удаляет лишние. Результат — папка
`<dest>/<группа>/<slug>.jpg`, готовая для `assets.load_or_build`; каталог уже заполнен описаниями, второй раз
ничего не описывается.

```sh
scripts/serve_llm.sh start agent
scripts/fetch_demo.py "сделай ролик про семью" --dest /tmp/family     # + контактный лист <dest>/.contact_sheet.jpg
python3 -m assemblee run --assets /tmp/family --task "сделай ролик про семью" --seconds 30
```

```python
from assemblee import fetch
fetch.search_images("family dinner", 10, orientation="vertical")         # нормализованные результаты
fetch.download(results, "/tmp/x", max_images=10, group="dinner")          # + /tmp/x/credits.json
fetch.gather(task, llm, "/tmp/x", per_query=6, max_total=30, on_event=lambda t, d: log.emit(t, **d))
```

- **Титры обязательны:** `<dest>/credits.json` — по записи на файл (asset id → provider, title, page_url,
  image_url, license, license_url, author, attribution, license_clear). Для CC BY / BY-SA указывайте `attribution`.
- `<dest>/.rejected.json` — отбракованные зрением (с описанием), повторный запуск их не скачивает.
- `on_event(type, data)` шлёт `tool_call`/`tool_result`/`warning` в формате [docs/events.md](docs/events.md)
  (имена: `plan_image_queries`, `search_images`, `download_images`, `download_image`, `check_image`, `gather_images`).
- Лимиты: Openverse анонимно 20 запросов/мин и 200/день (запросы разнесены на 3 с), `upload.wikimedia.org`
  отвечает 429 скриптам, поэтому файлы Commons берутся как миниатюры стандартных размеров с
  `thumb.wikimedia.org`, по одному. Локальный SearXNG (`providers=(..., "searxng")`, 127.0.0.1:8081)
  подключается только явно и только если доступен; его результаты с лицензией `unknown`.

## Музыка из интернета (`assemblee/music.py`)

Кроме четырёх синтезированных подложек можно взять настоящие треки CC/PD: `gather_music(task, llm, dest, moods)`
просит модель (JSON-схема) дать 3–6 английских запросов на каждое настроение (без модели — запросы по словам
имени настроения), ищет в **Openverse audio** (`category=music`, `license_type=commercial,modification`,
в основном Jamendo), **ccMixter** (публичный `api/query`, NC/sampling+ отбрасываются, есть свой bpm) и
**Wikimedia Commons** (`filetype:audio`, производный mp3), берёт инструментальные 30–300 с, скачивает
(≤ 40 МБ), переводит в wav 48 кГц стерео с `loudnorm I=-16` → `<dest>/music/<slug>.wav`, пишет запись
`kind: "music"` в тот же `<dest>/credits.json`.

Анализ без LLM и numpy, только ffmpeg: энергия трёх полос 100 кадров/с → onset-огибающая → автокорреляция
(темп, приор около 120 bpm) → DP-трекер долей (Ellis 2007) → самое громкое 10-секундное окно (`best_start`,
«дроп», на доле). На синтезированных: chiptune 120.0 bpm, epic 139.7 bpm.

```python
from assemblee import music
lib = music.gather_music(task, llm, "/tmp/x", {"warm": "семейные воспоминания", "dark": "ретро-хоррор"})
edl.music_library = {t["id"]: t for t in lib}       # или music.load_library("/tmp/x")
sec.music = lib[0]["id"]; sec.music_start = None     # None = с дропа; число = секунда трека на первой склейке
music.snap_edl(edl)                                   # склейки на доли, длительность секции ±5 %
music.beat_snap(durations, beats, offset)             # то же как чистая функция
```

Компилятор ставит трек так, что `music_start` приходится ровно на первую склейку секции (`sourceIn`),
кроссфейды между подложками прежние. Проверка: `scripts/smoke_music.py [dest] [out.mp4] [--llm]`.

## Зависимости

Python 3.12 + Pillow + aiohttp, ffmpeg, бинарники FilmCraft 0.20.1 и EffectCraft 0.24.1 (пути в
`assemblee/config.py`, переопределяются переменными `ASSEMBLEE_*`), llama.cpp `llama-server` с Vulkan/CUDA.
